## 2026-11-13 — 代码修改必须用完整 diff 格式

- 客户回复中贴代码修改时，必须使用完整的 `git unified diff` 格式：`--- a/path` + `+++ b/path` + `@@` hunk header + 上下文行。
- 路径不能是泛型通用路径（如 `a/drivers/usb/xxx.c`），必须对应 Bug 所在基线的真实 Gerrit 仓库路径，从 `platform/manifest` 或 `CODE_INDEX.md` 获取。
- 客户收到回复后应能直接 `git apply` 到本地仓库，不需要手动找文件路径。

## 模板：如何添加反馈

```markdown
## YYYY-MM-DD — {简短描述}

- {反馈条目1}：{具体问题描述}
- {反馈条目2}：{具体问题描述}
```

示例：
```markdown
## 2026-11-15 — 回复太啰嗦

- 不要在回复开头说"帮贵司分析了一下"，直接说结论
- "请参考附件"不如"附件是修改后的 dts 文件"
```
