缺陷分析

sgm41512_set_voltage() 在调压时直接调用 regmap_write() 写入 charger IC 寄存器， 未获取 I2C adapter 锁。当 BC1.2 检测模块（sprd_bc1p2.c::vbos_ok_work）并发访问同一 I2C 总线时， 产生传输冲突，导致 regmap_write() 返回 -EAGAIN 并触发重试。 每次重试间隔约 150ms，3 次重试累计延迟 450ms，直接导致 tPSTransition 超标。

并发竞争路径:
Thread A: sprd_tcpm (pd_notify) → sgm41512_set_voltage() → regmap_write() (I2C 写)
Thread B: vbos_ok_work (workqueue) → sprd_bc1p2_detect() → i2c_transfer() (I2C 读)
两者共用同一 I2C adapter，无互斥保护。

修复建议 (含代码 Diff)

⭐ 方案 A（推荐）— I2C 总线锁保护

修改位置: sgm41512_charger.c::sgm41512_set_voltage()

修改内容: 在电压调节期间获取 I2C adapter 锁，防止 BC1.2 并发访问

// 修复前 (Line 842) ret = regmap_write(chip->regmap, SGM41512_REG_VOLTAGE, target_mv); // 修复后 struct i2c_adapter *adapter = chip->client->adapter; i2c_lock_bus(adapter, I2C_LOCK_ROOT_ADAPTER); ret = regmap_write(chip->regmap, SGM41512_REG_VOLTAGE, target_mv); i2c_unlock_bus(adapter, I2C_LOCK_ROOT_ADAPTER);

预期效果: 调压期间 BC1.2 检测被阻塞，I2C 写入一次成功（< 5ms），总 tPSTransition 降至 < 100ms

风险: 低 — 锁持有时间极短 (< 5ms)，不影响 BC1.2 检测功能

💡 方案 B（备选）— 调压期间暂停 BC1.2 检测

修改位置: sprd_charger_main.c::set_voltage() + sprd_bc1p2.c

修改内容: 在 charger 主驱动层增加 flag，调压前通知 BC1.2 暂停，调压完成后恢复

预期效果: 同样可避免 I2C 竞争

风险: 中 — 需要跨模块协作，增加耦合，且 BC1.2 检测延迟可能影响其他测试项
