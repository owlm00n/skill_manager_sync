🎯 根因结论

SC27XX PD 控制器硬件 TX 自动重试机制（SC27XX_PD_AUTO_RETRY = BIT(0)） 在未收到 GoodCRC 时，以 ~1-2ms 间隔自动重传 Source Capabilities 消息。 软件层面每个 TX 周期只发起一次发送，但硬件在 CC 线上产生 4 条消息 （1 次发送 + 3 次硬件重试）。测试仪将这 4 条消息计为独立的消息 1-4，导致消息 3→4 间隔仅 ~1-2ms，远小于 PD 规范要求的 ≥100.9ms。

增加软件延迟（150→180ms）无效，因为硬件重试间隔不受软件参数影响。修复方案为禁用 enable_tx_auto_retry，由软件重试机制（150ms）替代硬件自动重试。

🔗 证据链

  1. [Phase 2] 失败定位 — 仪器报告: Error(0x0000021D): Source Capabilities message(4) was received before 100.9 ms。 步骤 5c.ii 要求消息 3→4 间隔 ≥100.9ms，实际测量 ~1-2ms。
  2. [Phase 3] Trace 分析 — 软件层面: 每个 TX 周期一次 PD TX complete, status: 2，间隔 150ms。 硬件层面: CC 线 4 条消息/TX 周期，间隔 ~1-2ms。测试仪将同一 TX 周期的硬件重传计为独立消息。
  3. [Phase 4] Log 分析 — 9 个 TX 周期，全部 int sts = 0x40，status: 2，Duration 8-13ms。 测试仪 burst 模式: 3 次连接/断开，每次断开时处于 SRC_SEND_CAPABILITIES 状态。 CC 极性交替（polarity 0→1→0）。无 I2C/Charger/BC1.2 异常。
  4. [Phase 5] 历史参照 — Bug 2743733 (UMS9230, 95% 相似) 和 Bug 2758082 (UMS9230H, 95% 相似) 均为 TEST.PD.PROT.SRC3.01 相同失败，均已 FIXED。
  5. [Phase 6] 代码定位 — 修复涉及 6 个文件: sc27xx_pd.c, sprd_tcpm.c, sc27xx_typec.c, musb_sprd.c, 头文件和 DTS。6 个 fix point 在状态机关键路径禁用 enable_tx_auto_retry。
